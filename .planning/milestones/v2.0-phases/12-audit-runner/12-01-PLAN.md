    **Step 1 — Resolve category (per D-03 from CONTEXT.md and Pitfall 4):**
    ```typescript
    const categoryGroup: CategoryGroup = getCategoryGroup(row.baseCategory) ?? 'tops';
    if (!getCategoryGroup(row.baseCategory)) {
      logger.warn(`[audit-runner] Unknown category '${row.baseCategory}' for ${row.styleID} — defaulting to tops`);
    }
    ```

    **Step 2 — Score existing images from sheet URLs:**
    For each view (front, back, side), read URL from `row.FrontImage`, `row.BackImage`, `row.DirectSideImage`. If URL is empty/falsy, mark as missing. If URL exists, call `downloadImage(url)` then `scoreImageQuality(buffer, categoryGroup)`. Wrap in try/catch — if download fails, treat as missing (log warning, continue). Store results in a `Map<'front'|'back'|'side', { buffer: Buffer; verdict: 'pass'|'fail'; score: number } | null>`.

    **Step 3 — Source missing/failed views (per D-03):**
    If ANY view is missing or has verdict 'fail', call `sourceImages(row.styleID, row.colorName)` ONCE. For each view that needs sourcing: if `sourced[view]` is non-null and has verdict 'pass', download the buffer via `downloadImage(sourced[view].url)` and use it. If sourced verdict is 'fail', still download buffer but mark for potential AI replacement.

    **Step 4 — AI generate/enhance remaining gaps:**
    - Front with verdict 'fail' (and buffer available): call `enhanceFrontImage(buffer, costTracker, categoryGroup)`. If returns null (budget), mark 'skipped'. If returns result, use the enhanced buffer.
    - Back/side still missing or failing AND front buffer is available: call `generateGarmentView(frontBuffer, view, categoryGroup, row.colorName, costTracker)`. If returns null, mark 'skipped'. If returns result, use the generated buffer.
    - Track AI cost: sum up `result.totalCost` or `result.cost` from each AI call.

    **Step 5 — Standardize ALL views (per D-02 — always re-standardize):**
    For every view where we have a buffer (whether pass-existing, sourced, generated, or enhanced): call `standardizeImage(buffer, categoryGroup)` then `uploadStagedImage(shopifyClient, stdBuffer, filename)`. Filename convention: `${row.productName}-${row.colorName}-${view}-std.png` with spaces replaced by dashes, lowercased.

    **Step 6 — Write CDN URLs to Google Sheets (per D-04):**
    Collect `{ front?: cdnUrl, back?: cdnUrl, side?: cdnUrl }` from Step 5. Call `buildStandardizationUpdates(sheetName, rowIndex, urls)` — pass rowIndex as-is (0-based, per Pitfall 5). Call `writeUpdates(sheetsClient, spreadsheetId, updates)`.

    **Step 7 — Build and return AuditResult:**
    Assemble `ViewAuditResult[]` for each view with correct status, score, cdnUrl, and optional reason. Return `{ styleId, colorName, views, cellsWritten, aiCostIncurred, error: undefined }`.

    **Error handling:** Wrap the entire function body in try/catch. If a catastrophic error occurs (not per-view), set `error` on AuditResult and return partial results. Per-view errors are non-fatal — log with `logger.warn` and continue.

    **IMPORTANT decision tree for each view:**
    1. Existing image passes scoring -> use existing buffer (status: 'pass-existing')
    2. Existing image fails scoring -> try sourcing first
    3. No existing image -> try sourcing first
    4. Sourced image available with pass verdict -> use sourced buffer (status: 'sourced')
    5. Sourced image available with fail verdict AND front exists -> try AI (for back/side: generate; for front: enhance)
    6. Sourced image available with fail verdict AND no AI available -> use sourced anyway (status: 'sourced')
    7. No sourced image AND front exists -> try AI (status: 'generated' or 'enhanced')
    8. AI returns null (budget) -> status: 'skipped', reason: 'budget exhausted'
    9. No front buffer at all -> back/side cannot be AI-generated, status: 'failed', reason: 'no front image available for AI generation'

    Run tests — all 8 MUST pass. Commit: `feat(12-01): implement auditProductImages pipeline`
