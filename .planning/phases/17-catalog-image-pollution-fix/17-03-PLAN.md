<objective>
Build the standalone Model* image rebuild tool `scripts/fix-model-images.ts`. This addresses 312 of 453 (69%) detected pollution events in the 2026-05-14 production audit — the biggest single yield of Phase 17. Per D-17-01 the script is structurally separate from `scripts/fix-image-pollution.ts` (different supplier API path, different verifier semantics, different cost profile). Per D-17-02 the work is split into two sub-tasks gated by a 10-pid sample-test (~$0.30) that MUST score ≥ 7/10 verifier-pass before committing to the full 213-pid run.

Tier ladder per pid + per Model column:
1. **Tier 1 (free)** — Fetch S&S `colorOnModel{Front,Side,Back}Image` for the matching color via a small helper that calls `/products/?style=N&fields=colorName,colorOnModelFrontImage,colorOnModelSideImage,colorOnModelBackImage` and client-side filters on `colorName`. Verifier-after-fix compares the downloaded model image vs the current BR FrontImage (Phase 16 SoT pattern). On pass → write Drive + BR. On fail → cascade to Tier 2.
2. **Tier 2 (~$0.03/call)** — Call `generateModelImage(frontBuf, gender, costTracker, openai)` from `src/lib/ai-model-image.ts`. Verifier-after-fix on the generated image vs the current BR FrontImage. On pass → write. On fail → cascade to manual queue (Plan 17-05).

Purpose: convert Model* pollution from an unsolved class (Phase 16 Tier 2 only handles BackImage + DirectSideImage) to a tractable automated fix. Validate the verifier-pass-rate assumption (A17-6) before scaling, since `generateModelImage` against `verifySameProduct` is empirically untested.

Output:
- New file `scripts/fix-model-images.ts`.
- New file `tests/scripts/fix-model-images.test.ts` (DI-seam pattern from `tests/scripts/fix-image-pollution.test.ts`).
- Task 1 produces `tmp/fix-model-images-sample-{date}.json` with `sample_pass_rate`, per-pid statuses, costs.
- Task 2 (gated by Task 1) produces `tmp/fix-model-images-full-{date}.json` + commits BR + Drive mutations + trail rows for the 213-pid corpus.

NOTE: this plan has `autonomous: false` because Task 1 ends in a sample-test result that requires operator review before Task 2 launches. The operator can re-run `/gsd-execute-phase 17` once they confirm the sample pass-rate. Task 2 is autonomous once unblocked.
</objective>
