  <behavior>
    - validateProduct returns { valid: true, data } for a complete SupplierProduct object
    - validateProduct returns { valid: false, errors: string[] } when required fields are missing (no title, no images, no variants, no fabricComposition)
    - Each error string identifies the specific field path that failed (e.g., "title: Required")
    - validateProduct rejects empty images array with specific error
    - validateProduct rejects empty variants array with specific error
    - validateProduct accepts valid Canada Sportswear product shape (with sizeChartUrl, null sizeChartData)
    - validateProduct accepts valid S&S product shape (with sizeChartData, null sizeChartUrl)
  </behavior>
  <action>
1. Create test fixtures FIRST (these are sample API responses for both suppliers):
   - `tests/suppliers/fixtures/csw-products-sample.json`: A minimal array of 2 Canada Sportswear products matching the CSWRawProduct shape from research (id, title, handle, body_html with fabric text and PDF link, variants with option1=Color/option2=Size, images array). Use realistic but fake data.
   - `tests/suppliers/fixtures/csw-body-html-sample.html`: Sample body_html containing "280 gsm - 8.3 oz./yd2 - 14 oz./lin. yd 70% cotton, 30% polyester vintage wash fleece" text and an `<a href="https://example.com/size-chart.pdf">` link.
   - `tests/suppliers/fixtures/ss-style-sample.json`: Array with one S&S Style object (styleID, partNumber, title, description with HTML containing "60% cotton, 40% polyester", baseCategory, styleImage).
   - `tests/suppliers/fixtures/ss-products-sample.json`: Array of 3-4 S&S Product objects (sku, colorName, sizeName, piecePrice, customerPrice, colorSwatchImage, colorFrontImage).
   - `tests/suppliers/fixtures/ss-specs-sample.json`: Array of 3-4 S&S Spec objects (sizeName, specName, value).

2. Create `src/suppliers/types.ts`:
   - Define and export: `ProductImage` (url: string, alt?: string), `SupplierVariant` (color, size, sku?, price?, colorSwatchImage?, colorFrontImage?), `SizeSpec` (sizeName, specName, value).
   - Define and export `SupplierProduct` interface: styleNumber, supplier ('canada-sportswear' | 'ss-canada'), title, description, category, fabricComposition, sizeChartUrl (string | null), sizeChartData (SizeSpec[] | null), images (ProductImage[]), variants (SupplierVariant[]), rawData (unknown).
   - Define and export `SupplierAdapter` interface: supplier property, fetchProducts(), fetchProduct(identifier).
   - Create Zod schemas: `ProductImageSchema`, `SupplierVariantSchema`, `SizeSpecSchema`, `SupplierProductSchema` matching the interfaces. Required fields: styleNumber (min 1), supplier (enum), title (min 1), description (min 10), fabricComposition (min 5), images (min 1), variants (min 1).
   - Export `ValidationResult` type: `{ valid: true; data: SupplierProduct } | { valid: false; errors: string[] }`.
   - Export `validateProduct(product: unknown): ValidationResult` function using safeParse. Map Zod errors to readable strings: `"${path.join('.')}: ${message}"`.

3. Create `src/lib/logger.ts`:
   - Create and export a winston logger with console transport, timestamp format, `info` level default.
   - Format: `[timestamp] [level]: message`

4. Write tests in `tests/suppliers/validation.test.ts` BEFORE running (TDD red phase):
   - Test valid CSW product passes validation
   - Test valid S&S product passes validation
   - Test missing title returns error with "title" in path
   - Test empty images array returns error
   - Test empty variants array returns error
   - Test missing fabricComposition returns error
   - Test multiple missing fields returns multiple errors

5. Run tests -- expect RED first, then implement types.ts to make them GREEN.
