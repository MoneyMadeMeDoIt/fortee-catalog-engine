  <action>
1. **Install sharp**: `npm install sharp` and `npm install -D @types/sharp` (if types are separate; sharp may bundle its own types).

2. **Create `src/shopify/image-standardizer.ts`** with these exports:

   **`standardizeImage(imageBuffer: Buffer): Promise<Buffer>`**
   - Uses sharp to resize to 2000x2000 with `fit: 'contain'`, white background `{ r: 255, g: 255, b: 255, alpha: 1 }`
   - Outputs PNG format
   - Pure function, no side effects

   **`downloadImage(url: string): Promise<Buffer>`**
   - Fetches image from URL using native `fetch`
   - Returns Buffer via `Buffer.from(await response.arrayBuffer())`
   - Throws descriptive error on non-OK response (include URL and status code)
   - 30 second timeout using AbortController

   **`uploadStagedImage(client: ShopifyClient, buffer: Buffer, filename: string): Promise<string>`**
   - Calls `STAGED_UPLOADS_CREATE` mutation with `{ resource: 'IMAGE', filename, mimeType: 'image/png', fileSize: String(buffer.length), httpMethod: 'PUT' }`
   - PUTs the buffer to the returned `target.url` with `Content-Type: image/png`
   - Returns the `target.resourceUrl` (this is what productSet uses in files)
   - Throws on userErrors or upload failure
   - NOTE: Import STAGED_UPLOADS_CREATE from mutations.ts. If plan 01 hasn't run yet, the executor should add the mutation string inline and remove it once plan 01 completes. However since both plans run wave 1, order may vary -- the executor should handle this.

   **`processProductImages(client: ShopifyClient, imageUrls: { front?: string; back?: string; side?: string }, productName: string, colorName: string): Promise<FileSetInput[]>`**
   - For each non-empty URL: download -> standardize -> upload staged -> collect FileSetInput
   - Front image: alt = "Front Print"
   - Back image: alt = "Back Print"
   - Side image: alt = `${productName} - ${colorName} Side`
   - Each FileSetInput: `{ originalSource: resourceUrl, alt, contentType: 'IMAGE' }`
   - If a single image fails to download/process, log warning and skip it (do not fail the entire product)
   - Use winston logger for warnings

   Type the client parameter as: `{ request: (query: string, options: { variables: Record<string, unknown> }) => Promise<unknown> }` to match the existing pattern in the codebase.

3. **Create `tests/shopify/image-standardizer.test.ts`**:
   - Test `standardizeImage`: Create a small test image buffer (e.g., 100x100 red PNG created with sharp), pass through standardizeImage, verify output is 2000x2000 PNG using `sharp(output).metadata()`
   - Test `downloadImage`: Mock fetch to return a buffer, verify it returns the buffer. Mock fetch to return 404, verify it throws with URL in message.
   - Test `uploadStagedImage`: Mock client.request to return staged target, mock global fetch for PUT, verify it calls STAGED_UPLOADS_CREATE with correct variables and returns resourceUrl.
   - Test `processProductImages`: Mock all underlying functions, verify correct alt text assignment, verify skipped images on download failure.
   - Use `vi.mock` and `vi.fn` for mocking.
